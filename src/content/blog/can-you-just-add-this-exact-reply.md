They already paid. The work is underway. Then the message lands: “Can you just add this one thing?”

It sounds small. You know it is not. If you say yes every time, the project that was priced for 8 hours becomes 14 and you have no record of the change. If you say no flat, they feel nickel-and-dimed and the next referral dies.

You need the exact words that keep the original scope intact while still sounding like the person who solves problems.

## The 60-second log before you reply

Open the same note you use for the Monday scan. Add one line.

```
Name: ________
Original scope: ________
Request: ________
Asked on: ________
Reply sent: ________
Decision: hold / change order / no
Next touch: ________
```

If you cannot name the original scope in one sentence, do not reply yet. That sentence is the whole boundary.

## Exact reply that protects the price without the fight

Send this before noon on a weekday. Subject: Re: [Project name]

> Got it. That sits outside the [original scope]. I can add it as a change order for [X hours / $Y] and deliver by [date]. Want me to send the one-pager, or keep the original plan?

One paragraph. Binary. The date and the price make the decision concrete. “Want me to send the one-pager” gives them an easy yes instead of an argument.

Do not explain why it is extra. Do not apologize. Do not offer a free sample.

## What you do when they reply

- Yes, send the one-pager: send the short change-order note the same hour. New invoice, new date, original scope still the record. Log the decision as change order. Do not start the extra work until the money is in.
- Keep the original plan: reply “Understood. Staying with the original scope. Next milestone still [date].” Status = hold. Next touch = the date you already had.
- Can you do it cheaper / just this once: repeat the same binary once. “I can add it for [price] by [date], or we stay with the original. Which works?” Do not negotiate in the same thread.
- Silence after 48 hours: no second email. The original scope continues. Mark the request closed.

## Exact one-pager fields for the change order

If they say yes, the one-pager is four lines. Paste them into the same note, then send.

```
Change: ________
Price: $________
Delivery: ________
Original scope unchanged: yes
```

Subject: Change order — [Project name]

Attach nothing. The four lines are the document. After payment lands, update the log and add the new date to the Monday scan.

## Timing that keeps the boundary clean

- Reply the same day before 3pm. After that it looks like you stewed on it.
- Never Friday afternoon. The thread dies over the weekend and Monday starts with the original scope already blurred.
- If the request arrives after 3pm, send the reply the next morning before 11am. Same words.
- Cap open change-order rows at two. More than two means the original scope was never written down.

## Extra concrete steps that stop “just this once” from becoming the new scope

1. Write the original scope sentence in the log the day the deposit clears. Without that sentence the reply has nothing to point at.
2. Keep the reply template in the same note as the Monday scan. One open, both available.
3. After any change order is paid, add one line to the next weekly reset: “Change order closed on [name]. Original scope still [sentence].”
4. If they ask a second time inside the same project, send the identical binary. Do not soften it.
5. Never start the extra work on a verbal yes. The one-pager and the payment are the record.
6. At the end of the project, the wrap-up email restates the original scope plus any paid change orders. No surprises in the final invoice.
7. If you cannot name a price for the add in under 60 seconds, the request is bigger than “just this.” Say so and book a 15-minute call instead of guessing in email.
8. Screenshot the original proposal or contract into the project note the day you start. Memory of what you sold is not a boundary.

## Fill-in after every send or reply

```
Touch sent: ________ (date/time)
Reply: yes one-pager / keep original / cheaper / silent
Decision logged: ________
Next action: one-pager + invoice / continue original / closed
Change order paid: yes / no
```

## Why this works when “I’ll try to squeeze it in” fails

“I’ll try to squeeze it in” trains them that the scope is elastic and trains you that your price was a suggestion. The binary reply makes the choice visible and time-bound. You stop rebuilding the boundary from memory every time a mid-project message arrives.

## What still breaks when the reply only lives in a note

You can paste it today. It works until a slammed Thursday. Then the request sits in the inbox, the original scope sentence is gone, and by Friday you have already started the extra work because saying no felt harder than doing it.
